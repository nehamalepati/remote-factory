## 1. Problem Statement

Remote Factory is an autonomous software evolution harness that detects project
state, delegates improvement work to specialist AI agents, evaluates every change
against a composite metric, and accumulates institutional knowledge across
experiments and projects — all without human intervention.

It solves six specific operational problems:

- It **detects** what a project needs (tests, lint, type checks, evals) instead
  of requiring manual triage before every improvement attempt.
- It **delegates** implementation, research, and verification to purpose-built
  agent roles instead of relying on a single monolithic prompt.
- It **evaluates** every change quantitatively with pre/post composite scoring
  instead of accepting untested or unverified changes.
- It **reverts** changes that degrade the composite score instead of silently
  accumulating regressions.
- It **prioritizes** hypotheses through the FEEC heuristic (Fix > Exploit >
  Explore > Combine) instead of random or recency-biased selection.
- It **archives** experiment outcomes, patterns, and agent playbook evolutions
  instead of discarding institutional knowledge between sessions.

**Important boundary:** The factory improves source code and manages experiments.
It does NOT deploy artifacts, serve production traffic, manage cloud
infrastructure, or provide an IDE integration. It delegates to CLI backends
(Claude Code, Bob Shell, OpenAI Codex, OpenCode) but is not coupled to any
single provider.

## 2. Goals and Non-Goals

### 2.1 Goals

1. **Detect project state** from filesystem and git metadata and select the
   appropriate workflow mode automatically.
2. **Dispatch specialist agents** through typed workflow graph nodes with
   per-role timeouts, model overrides, and prompt resolution.
3. **Evaluate every change** against a composite score composed of mandatory
   hygiene dimensions, growth dimensions, and optional project-specific
   dimensions.
4. **Enforce atomic keep/revert decisions** per experiment so that no change
   degrades the codebase without explicit override.
5. **Prioritize hypotheses** via the FEEC heuristic with stuck detection,
   anti-pattern detection, and plateau detection.
6. **Accumulate cross-project knowledge** through the archive, insights pipeline,
   and ACE playbook evolution.
7. **Support pluggable CLI backends** without coupling to any single LLM
   provider.
8. **Define all modes as directed workflow graphs** from a fixed set of node
   primitives, ensuring new modes compose from existing building blocks.
9. **Emit structured events** for every agent invocation, gate verdict, and
   workflow transition to enable observability and debugging.
10. **Recover from crashes** via checkpoint/resume so that long-running cycles
    can survive process termination.

### 2.2 Non-Goals

- **IDE integration.** The factory is a CLI-first harness, not an editor plugin.
  (Extension via MCP server is available for tool-calling agents.)
- **Real-time pair programming.** The factory operates in batch cycles, not
  interactively within a coding session. Design mode's user gates are the
  exception.
- **Language-specific strategies.** Language-aware evaluation is auto-detected
  via `LanguageEvaluator` plugins; the factory MUST NOT hardcode
  language-specific improvement strategies in its core logic.
- **Deployment.** The factory produces source code changes and PRs; deploying
  artifacts to production is out of scope.
- **Multi-tenancy.** The factory runs as a single-user CLI tool. Concurrent
  users sharing the same `.factory/` directory is not supported.

### 2.3 Design Philosophy

Separation of concerns drives the architecture: the CLI provides pure tools, the
workflow engine defines structure, the CEO agent makes decisions, and specialist
agents do work. Every change is measured — the FEEC heuristic prevents thrashing
and the composite score prevents regression. Workflows are directed graphs of
typed primitives; new modes MUST be assembled from the same node types as
existing ones.

## 5. Architecture Overview

### 5.1 Abstraction Levels

1. **Layer 1: CLI Tools (`factory/cli/`)** — Pure, stateless subcommands that
   translate user intent into calls to Layers 2–4. Each subcommand is a `cmd_*`
   function dispatched via a handler dict. The CLI MUST NOT contain business
   logic.

2. **Layer 2: Workflow Graph Engine (`factory/workflow/`)** — Defines all factory
   modes as directed graphs of typed nodes. The same graph definition MUST
   produce two execution formats: headless (deterministic DAG walker) and
   interactive (Claude Code SKILL.md playbooks).

3. **Layer 3: CEO Agent** — The orchestrating agent. Receives `ceo.md` as its
   system prompt, detects project state, then reads the appropriate SKILL.md
   playbook. The CEO MUST delegate all implementation, research, and verification
   to specialist agents — it MUST NOT write code, run tests, or perform research
   directly.

4. **Layer 4: Specialist Agents (`factory/agents/`)** — Purpose-built
   subprocesses spawned by the CEO via `factory agent <role>`. Prompt resolution
   follows a two-tier lookup: project-specific override then factory default.
   ACE-evolved playbooks are auto-injected.

### 5.2 Data Flow Summary

A factory cycle begins with **state detection**: `detect_state()` inspects the
project's filesystem and git metadata to determine one of five `ProjectState`
values. The state selects a workflow, which is a directed graph of `AgentNode`,
`FnNode`, `GateNode`, `ForkNode`, `JoinNode`, `SubgraphForkNode`, and
`SelectionNode` primitives. The workflow executor walks the DAG, spawning
specialist agents at `AgentNode`s, running shell commands at `FnNode`s, and
evaluating verdicts at `GateNode`s. Each experiment passes through the
`ExperimentStore` lifecycle: `begin()` → eval-before → builder → eval-after →
`finalize(keep|revert)`. All events are logged to `.factory/events.jsonl`. At
cycle end, the archivist records learnings, and the ACE pipeline MAY evolve agent
playbooks based on accumulated performance data.

## 6. Domain Model

### 6.1 ProjectState

An enumeration of five mutually exclusive states a target project can occupy.
`detect_state()` MUST evaluate these in a fixed order (§7.1) to resolve
ambiguity.

Values: `NO_REPO`, `REPO_INCOMPLETE`, `NO_FACTORY`, `EVALS_PENDING_REVIEW`,
`HAS_FACTORY`.

### 6.2 FactoryConfig

The machine-readable project configuration stored at `.factory/config.json`,
parsed from the user-facing `factory.md` markdown file.

- `goal: str` — REQUIRED. The project's improvement objective.
- `scope: list[str]` — REQUIRED. Directories/files the factory may modify.
- `guards: list[str]` — REQUIRED. Conditions that trigger mandatory revert.
- `eval_command: str` — REQUIRED. Shell command to run project-specific evals.
- `eval_threshold: float` — REQUIRED. Minimum score to pass precheck.
- `constraints: list[str]` — REQUIRED. Hard boundaries the factory must respect.
- `hypothesis_budget: HypothesisBudget` — Controls backlog-first hypothesis
  generation. Default: `min_growth=2, max_new=2`.
- `target_branch: str` — Default: `"main"`.
- `smoke_test: str` — Quick validation command run before full eval.
- `project_eval: list[ProjectEvalDimension]` — User-defined eval dimensions.
- `eval_weights: EvalWeights` — Weight distribution across hygiene/growth/project
  tiers. MUST normalize so all three sum to 1.0.
- `research_target: ResearchTarget | None` — Research mode objective and metric.
- `inner_loop: InnerLoopConfig | None` — Multi-run execution per cycle.
- `outer_loop: OuterLoopConfig | None` — What happens when inner loop plateaus.
- `mutable_surfaces: list[str]` — Files agents MAY modify in research mode.
- `fixed_surfaces: list[str]` — Files agents MUST NOT modify.
- `hard_constraints: list[HardConstraint]` — Shell commands that must exit 0;
  non-zero exit = mandatory revert. The CEO cannot override this.
- `adversarial: AdversarialConfig | None` — GAN-style adversarial eval loop.
- `parallel: ParallelConfig | None` — Parallel hypothesis execution.
- `clean_pr: bool` — Strip non-essential artifacts from PRs. Default: `False`.
- `test_timeout: int` — Timeout for test commands. Default: 600. MUST be ≥ 1.

Every `FactoryConfig` instance MUST be validated via Pydantic strict mode with
`extra="forbid"`. Any unrecognized key in the JSON MUST raise a validation error.

### 6.3 ExperimentRecord

One row in `results.tsv` plus the per-experiment directory.

- `id: int` — Auto-allocated under filelock.
- `timestamp: datetime` — When the experiment was created.
- `hypothesis: str` — The proposed change description.
- `verdict: "keep" | "revert" | "error" | "superseded"` — Final outcome.
- `score_before: float | None` — Composite score before implementation.
- `score_after: float | None` — Composite score after implementation.
- `delta: float | None` — `score_after - score_before`. MUST be computed by
  `finalize()` if not already set.
- `cost_usd: float | None` — Total cost of the experiment.

`ExperimentRecord` MUST be serializable to TSV by `ExperimentStore.finalize()`.
The `superseded` verdict is reserved for parallel experiments where only one
branch wins.

### 6.4 CompositeScore

Aggregated result from all eval tiers plus guards.

- `total: float` — MUST be in [0.0, 1.0].
- `results: list[EvalResult]` — Individual dimension results.
- `guard_violations: list[str]` — Guard checks that failed.
- `passed: bool` — Whether `total ≥ eval_threshold` and no guard violations.

### 6.5 Workflow

A directed graph of typed nodes with labeled edges and a state-based trigger.

- `name: str` — Unique workflow identifier.
- `nodes: dict[str, NodeType]` — Map from node ID to typed node.
- `edges: list[Edge]` — Directed edges with optional `VerdictType` conditions.
- `start_node: str` — ID of the entry node.
- `trigger: TriggerFn | None` — Predicate `(ProjectState, context) → bool`.

Every `Workflow` MUST pass `validate_graph()` before registration. The validator
uses NetworkX to check: all edge endpoints exist, start node is reachable, no
orphan nodes, gate nodes have valid condition edges.

[[graph:factory.workflow.primitives]]

### 6.6 Verdict

Algebraic verdict type produced by gate nodes:

- `Proceed` — Continue to the next node via the `PROCEED`-conditioned edge.
- `Reloop(target, feedback, max_iterations)` — Return to a previous node.
  Feedback is appended to the target node's context. The executor MUST track
  iteration counts per `(gate, target)` pair and HALT when `max_iterations` is
  exceeded.
- `Halt(reason)` — Terminate the workflow. The `halt_reason` MUST be recorded in
  `ExecutionResult`.

A `Reloop` verdict MUST include a non-empty `target`. A `Halt` verdict MUST
include a non-empty `reason`. These invariants are enforced by Pydantic model
validation.

## 7. State Machines and Lifecycles

### 7.1 Project Lifecycle

The factory detects one of five `ProjectState` values and selects a workflow.
`detect_state()` MUST evaluate rules in this fixed order:

```
                    ┌─────────────┐
                    │   NO_REPO   │ ──build──► REPO_INCOMPLETE
                    └─────────────┘
                          │
                    (git init or clone)
                          ▼
                 ┌────────────────────┐
                 │  REPO_INCOMPLETE   │ ──build──► NO_FACTORY
                 └────────────────────┘
                          │
                    (plan issues closed)
                          ▼
                    ┌─────────────┐
                    │  NO_FACTORY │ ──discover──► EVALS_PENDING_REVIEW
                    └─────────────┘
                          │
                    (eval_profile.json created)
                          ▼
              ┌────────────────────────────┐
              │  EVALS_PENDING_REVIEW      │ ──review──► HAS_FACTORY
              └────────────────────────────┘
                          │
                    (human_reviewed=True + config.json)
                          ▼
                   ┌──────────────┐
                   │ HAS_FACTORY  │ ◄── improve / research / refine / meta
                   └──────────────┘
```

**Detection rules** (evaluated in order):

1. Path missing or no `.git` → `NO_REPO`
2. `eval_profile.json` exists with `human_reviewed=False` → `EVALS_PENDING_REVIEW`
3. `.factory/config.json` exists → `HAS_FACTORY`
4. Open GitHub issues with `plan` label → `REPO_INCOMPLETE`
5. Otherwise → `NO_FACTORY`

Rule 2 MUST be checked before rule 3 to handle the discover → review transition
where `eval_profile.json` exists but `config.json` does not yet.

### 7.2 Experiment Lifecycle

```
     begin(hypothesis)          save_eval(before)
           │                         │
           ▼                         ▼
    ┌──────────┐              ┌──────────────┐
    │ CREATED  │──builder──►  │  IN_PROGRESS │
    └──────────┘              └──────────────┘
                                     │
                              save_eval(after)
                                     │
                               ┌─────┴──────┐
                               │            │
                    finalize(keep)    finalize(revert)
                               │            │
                               ▼            ▼
                          ┌────────┐  ┌─────────┐
                          │  KEPT  │  │REVERTED │
                          └────────┘  └─────────┘
```

- `begin()` MUST allocate an experiment ID under filelock and register the
  project in the global registry.
- `finalize()` MUST compute delta from `score_before`/`score_after` if not
  already set.
- `finalize()` MUST append a row to `results.tsv` under filelock.
- The `superseded` verdict is reserved for parallel experiments where only one
  branch wins.

### 7.3 Verdict Lifecycle (Workflow Gates)

Gate nodes produce an algebraic `Verdict`:

```
Verdict = Proceed | Reloop(target, feedback, max_iterations) | Halt(reason)
```

Gate evaluators come in three types:
- `agent` — The CEO reviews output and emits a verdict.
- `fn` — A shell command runs and stdout is parsed into a verdict.
- `user` — In interactive mode, the user decides. In headless mode, auto-proceeds.

[[graph:factory.workflow.executor]]

### 7.4 Adversarial Eval Loop

When `FactoryConfig.adversarial` is configured, the factory operates a GAN-style
loop:

```
  ┌─────────────┐    threshold met      ┌───────────────────┐
  │  Generator   │──(hysteresis rounds)──►  Discriminator    │
  │  (active)    │◄──(hysteresis rounds)──│  (active)        │
  └─────────────┘                        └───────────────────┘
         │                                        │
         └────── both consecutive ≥ window ───────┘
                          │
                   ┌──────▼──────┐
                   │  CONVERGED  │
                   └─────────────┘
```

- Phase switching occurs when the active component scores at or above its
  threshold for `hysteresis` (default 3) consecutive rounds.
- Convergence is detected when both per-role consecutive counters independently
  reach `convergence_window` (default 5).
- State MUST be persisted to `.factory/adversarial_state.json` after every round.

## 8. Module Specifications

### 8.1 `factory/state.py`

**Role:** Project state detection — the entry point for all workflow selection.
**Layer:** 1 (Pure tool).

`detect_state()` MUST check for `NO_REPO` before any other state.
`detect_state()` MUST check `EVALS_PENDING_REVIEW` before `HAS_FACTORY` to
handle the discover → review transition. The `_has_open_plan_issues()` helper
calls `gh issue list` with a 15-second timeout; timeout or missing `gh` binary
MUST be treated as "no open issues" (returns `False`), not as an error.

Only the `plan` label signals an unbuilt repo. The `implementation` label MUST
NOT be checked — it is the factory's own backlog label, created on already-built
repos.

[[graph:factory.state]]

### 8.2 `factory/store.py`

**Role:** Experiment filesystem store — manages the `.factory/` directory.
**Layer:** 1 (Pure tool).

`ExperimentStore` MUST use `FileLock` for all writes to `results.tsv` and for
experiment ID allocation. `begin()` MUST auto-register the project in the global
registry. `finalize()` MUST append exactly one row to `results.tsv` per
experiment. `reparse_config()` MUST parse `factory.md` markdown into
`FactoryConfig` and write `.factory/config.json`.

The TSV schema is defined by `TSV_COLUMNS`: `id`, `timestamp`, `hypothesis`,
`change_summary`, `issue_number`, `pr_number`, `score_before`, `score_after`,
`delta`, `verdict`, `cost_usd`, `notes`, `research_citations`. Adding a field to
`ExperimentRecord` MUST be accompanied by a `TSV_COLUMNS` update.

[[graph:factory.store]]

### 8.3 `factory/eval/runner.py`

**Role:** Compute mandatory eval dimensions and merge with project-specific evals.
**Layer:** 1 (Pure tool).

The runner MUST compute 6 hygiene dimensions and growth dimensions for every
managed project. Projects MAY add dimensions via `eval/score.py` and
`project_eval` in `factory.md`, but MUST NOT remove mandatory dimensions. If a
tool is not detected for a hygiene dimension (e.g., no linter installed), its
score MUST be 0.5 (neutral), not 0.0.

Weight distribution: without project eval, MUST use 50% hygiene + 50% growth.
With project eval, weights are configurable via `EvalWeights` and MUST normalize
so all three tiers sum to 1.0.

[[graph:factory.eval.runner]] | [[graph:factory.eval.hygiene]] | [[graph:factory.eval.growth]]

### 8.4 `factory/strategy.py`

**Role:** FEEC priority heuristic and tiered experiment history.
**Layer:** 1 (Pure tool).

`categorize_hypothesis()` MUST check FIX keywords first, then EXPLOIT, then
COMBINE. Unmatched text MUST be classified as EXPLORE (catch-all). The keyword
lists are defined as module-level constants.

`detect_stuck()` MUST flag when the last N (default 3) consecutive reverts share
a FEEC category. `detect_plateau()` MUST surface when the last N consecutive
experiments show no score improvement.

Tiered history compression: Tier 1 (last 3) = full detail, Tier 2 (4–10 back) =
one-line summaries, Tier 3 (11+) = aggregate stats. Maximum inline history is
capped at 10 experiments.

[[graph:factory.strategy]]

### 8.5 `factory/agents/runner.py`

**Role:** Load prompts and invoke CLI backend instances.
**Layer:** 1 (Pure tool).

Prompt resolution follows a two-tier lookup: project-specific override at
`<project>/.factory/agents/<role>.md`, then factory default at
`factory/agents/prompts/<role>.md`. ACE-evolved playbooks from
`~/.factory/playbooks/<role>.md` are auto-injected via `inject_playbook()`.

The agent runner MUST track consecutive failures globally. After
`_FAILURE_ABORT_THRESHOLD` (default 2) consecutive failures, a
`ConsecutiveAgentFailureError` MUST be raised, aborting the cycle. Success
(return_code == 0) MUST reset the counter to 0.

Every invocation MUST emit `agent.started`, `agent.completed` or
`agent.failed`/`agent.timeout` events to `.factory/events.jsonl`.

The CEO prompt MUST include an identity re-anchor block (Sacred Rule 8) to
prevent role drift during long sessions.

[[graph:factory.agents.runner]]

### 8.6 `factory/workflow/definitions.py`

**Role:** Define all factory modes as directed workflow graphs.
**Layer:** 2 (Workflow engine).

This module MUST define workflow builder functions for all registered modes.
Each function returns a `Workflow` instance. The `_deep_qa_subgraph()` helper
constructs the reusable health_checker → code_reviewer → gate_review →
adversarial_tester pipeline shared by five core workflows.

`gate_review` is an `fn` gate that checks for `CRITICAL_FOUND` in code review
output. If `CRITICAL_FOUND` is present, the pipeline MUST short-circuit (skip
adversarial testing). The adversarial_tester has the highest timeout of any
non-CEO agent (1800s).

The builder loop MUST NOT exceed 3 reloop iterations on the `gate_qa → builder`
edge.

[[graph:factory.workflow.definitions]]

### 8.7 `factory/workflow/executor.py`

**Role:** Deterministic async graph walker implementing formal execution
semantics.
**Layer:** 2 (Workflow engine).

The executor MUST walk the DAG in topological order, respecting edge conditions.
For `ForkNode`s, all targets MUST be launched concurrently. For `JoinNode`s, the
executor MUST wait for all sources to complete. For `SubgraphForkNode`s, the
executor creates N independent `WorkflowExecutor` instances, each in an isolated
git worktree.

The executor MUST track reloop iteration counts per `(gate, target)` pair. When
`max_iterations` is exceeded, the verdict MUST be escalated to `Halt`.

`ExecutionResult` MUST record: `success`, `halted`, `halt_reason`,
`nodes_executed`, `node_outputs`, and `duration_ms`.

[[graph:factory.workflow.executor]]

### 8.8 `factory/workflow/skill_export.py`

**Role:** Convert workflow graphs to Claude Code SKILL.md playbooks.
**Layer:** 2 (Workflow engine).

`export_skills()` MUST produce one `SKILL.md` file per registered workflow under
`skills/workflow-*/`. The converter topologically sorts nodes and renders each
as a step in the playbook. Edge conditions are rendered as decision branches.

SKILL.md files are consumed by the CEO agent at runtime as mode-specific
playbooks. Changes to workflow graph definitions MUST be followed by
`factory workflow export-skills` to regenerate SKILL.md files.

[[graph:factory.workflow.skill_export]]

### 8.9 `factory/workflow/primitives.py`

**Role:** Define the composable node, edge, verdict, and workflow types.
**Layer:** 2 (Workflow engine).

`NodeType` is a union of: `AgentNode`, `FnNode`, `GateNode`, `ForkNode`,
`JoinNode`, `SubgraphForkNode`, `SelectionNode`, and `Study`. All node types
inherit from `Node`, which provides `id`, `reads`, `writes`, and `blocking`
fields.

`DEFAULT_AGENT_POOL` defines default model and timeout for each role. The CEO
gets the highest timeout (3600s). The archivist uses `haiku` model (lowest cost).

### 8.11 `factory/registry.py`

**Role:** Global project registry at `~/.factory/registry.json`.
**Layer:** 1 (Pure tool).

Projects MUST self-register on `ExperimentStore.begin()`. Registration is
idempotent — duplicate paths are silently ignored. The registry supports
auto-population from a directory scan via `populate_from_directory()`. Stale
entries (paths that no longer exist on disk) are skipped when queried but MUST
NOT be automatically pruned.

[[graph:factory.registry]]

### 8.12 `factory/eval/hygiene.py`

**Role:** Compute the 6 mandatory hygiene eval dimensions.
**Layer:** 1 (Pure tool).

Dimensions: `tests`, `lint`, `type_check`, `coverage`, `config_parser`,
`architecture`. Each dimension auto-detects its tool (pytest/jest/vitest for
tests, ruff/eslint/clippy for lint, etc.). Sub-project detection allows
multi-project repos (e.g., a monorepo with separate `pyproject.toml` files).

If a tool is not detected, the dimension MUST return a score of 0.5 (neutral).
The `_neutral()` helper encapsulates this contract.

[[graph:factory.eval.hygiene]]

### 8.13 `factory/eval/growth.py`

**Role:** Compute growth eval dimensions.
**Layer:** 1 (Pure tool).

Dimensions: `capability_surface`, `experiment_diversity`, `observability`,
`research_grounding`, `factory_effectiveness`, `spec_compliance`. Growth
dimensions measure the factory's own effectiveness and the project's maturity,
not just code quality.

[[graph:factory.eval.growth]]

### 8.14 `factory/adversarial.py`

**Role:** GAN-style adversarial eval loop state machine.
**Layer:** 1 (Pure tool).

Phase transitions use hysteresis (default 3 consecutive rounds above threshold).
Per-role streak counters (`generator_consecutive_above`,
`discriminator_consecutive_above`) are tracked independently. Convergence
detection requires both counters to reach `convergence_window` (default 5).

State MUST be persisted to `.factory/adversarial_state.json` after every round.
`reset_adversarial_state()` MUST clear all counters and history.

[[graph:factory.adversarial]]

### 8.15 `factory/checkpoint.py`

## 9. Shared Contracts

### 9.1 TSV History Format

The append-only `results.tsv` file uses tab-separated columns defined by
`TSV_COLUMNS` in `factory/store.py`. All writes MUST be protected by `FileLock`
at `.factory/.store.lock`. Column order MUST NOT change — new columns MUST be
appended to the end. The dashboard, ACE reflector, and insights pipeline all
consume this format.

### 9.2 Event Schema

Events in `.factory/events.jsonl` MUST include: `type`, `timestamp`, and
type-specific fields. Agent events MUST include `role`. Workflow events MUST
include `workflow_name` and `run_id`. Events MUST resolve symlinks before writing.

### 9.3 Agent Prompt Contract

Every agent prompt MUST be a standalone markdown file. The runner MUST inject ACE
playbooks after the base prompt. The CEO prompt MUST include an identity
re-anchor block. Project-specific overrides at
`.factory/agents/<role>.md` take precedence over factory defaults.

### 9.4 Eval Output Contract

Project-specific eval scripts MUST write JSON to stdout in the format:
`{"results": [...]}` where each result has `name`, `score`, `passed`, and
`details` fields. The score MUST be a float in [0.0, 1.0].

### 9.5 Runner Contract

Every runner implementation MUST satisfy the `Runner` protocol:
- `metadata() → RunnerMeta` — static capability description.
- `build_command() → (args, env, temp_files)` — construct the CLI invocation.
- `headless() → AgentRunResult` — non-interactive execution.
- `interactive_run() → int` — interactive execution returning exit code.

Runners with no token telemetry MUST enforce invocation ceilings. Every runner
MUST support dry-run mode via environment variables.

## 10. Configuration Specification

### 10.1 Configuration Sources and Precedence

Five-tier precedence (highest wins):

1. **CLI flag** — `--runner`, `--model`, `--profile`, etc.
2. **Environment variable** — `FACTORY_RUNNER`, `FACTORY_MODEL`, etc.
3. **Profile credential** — `~/.factory/config.toml [credentials.<name>]`
4. **config.toml default** — `~/.factory/config.toml [defaults]`
5. **Hardcoded default** — in source code

### 10.2 Core Config Fields

|-------|--------|------|---------|
| `runner` | All 5 tiers | `str` | `"claude"` |
| `model` | All 5 tiers | `str` | `""` (runner default) |
| `projects_dir` | Tiers 2–5 | `str` | `"~/factory-projects"` |

Profile names MUST be validated: alphanumeric, hyphens, and underscores only.
Credential keys MUST start with `FACTORY_` or be a recognized API key pattern.

### 10.3 Project Config (`factory.md` → `config.json`)

The parser MUST handle:
- Heading-based sections (H2 and H3) with a section name mapping.
- List items (`- key: value`) and continuation lines (indented).

## 12. Failure Model and Recovery

### 12.1 Failure Classes

- **Agent spawn failure** — CLI backend process fails to start or times out.
  Tracked by consecutive failure counter.
- **Eval failure** — Eval command returns non-zero or unparseable output.
  Produces `CompositeScore` with `total=0.0` and error details.
- **Gate halt** — A gate node emits `Halt(reason)`. The workflow terminates
  immediately.
- **Reloop exhaustion** — A gate reloops more than `max_iterations` times.
  Escalated to `Halt`.
- **Precheck failure** — Score regression or guard violation. Mandatory revert.
- **Hard constraint failure** — Shell command exits non-zero. Mandatory revert;
  CEO cannot override.
- **Workflow validation failure** — `validate_graph()` returns issues.
  Workflow MUST NOT be registered.

### 12.2 Recovery Behavior

Agent spawn failures: after `_FAILURE_ABORT_THRESHOLD` (default 2) consecutive
failures, a `ConsecutiveAgentFailureError` is raised, aborting the cycle. A
`cycle.aborted` event MUST be emitted before the exception propagates. This
prevents the CEO from falling back to doing work itself.

Eval failures: return a `CompositeScore` with `total=0.0` and error details. The
experiment SHOULD be finalized with verdict `"error"`.

Telemetry failures: MUST be swallowed silently — they MUST NOT block agent
execution or workflow progress.

### 12.3 Restart and Resume Semantics

`save_checkpoint()` serializes `CheckpointState` to `.factory/checkpoint.json`.
`factory resume /path` restores from the last checkpoint and continues the cycle.
The CEO SHOULD save checkpoints at each major state transition.

`load_checkpoint()` returns `None` if the file is missing or corrupt — the
factory MUST be able to start fresh when no checkpoint exists. Checkpoint data
does not survive across factory versions — a checkpoint from a different version
SHOULD be ignored.

## 13. Security and Safety

### 13.1 Trust Boundaries

- **Trusted:** Factory source code, workflow definitions, agent prompts shipped
  with the factory.
- **Semi-trusted:** Project-specific agent prompt overrides at
  `.factory/agents/<role>.md` and user-local playbooks at
  `~/.factory/playbooks/<role>.md` — written by the user or evolved by ACE.
- **Untrusted:** Agent stdout/stderr output, external web search results,
  project eval script output.

Agent output is captured as text and written to `.factory/reviews/`. It is
consumed by downstream agents but MUST NOT be executed as code by the factory
itself (except via explicitly sandboxed `FnNode` commands).

### 13.2 Filesystem Safety Invariants

- The factory MUST only write to the project directory and `~/.factory/`.
- `.factory/` SHOULD be added to the project's `.gitignore`.
- Worktree paths are scoped to the project's git repository.
- `ensure_factory_dir()` MUST remove broken or circular symlinks before creating
  directories.
- Path interpolation in `FnNode` and `GateNode` shell commands MUST use
  `shlex.quote()` to prevent command injection.

### 13.3 Secret Handling

- The factory MUST NOT commit secrets, API keys, or credentials.
- API keys in `~/.factory/config.toml` are injected into `os.environ` at runtime,
  not persisted to project files.
- The `.factory/` directory MAY contain sensitive auth files (e.g.,
  `.factory/.bob_auth`) — these MUST be gitignored.
- `factory config show` MUST mask secrets by default; `--reveal` explicitly
  un-masks them.

## 15. Extension Points

1. **Custom agent prompts:** Place `.factory/agents/<role>.md` to override any
   agent's prompt. The runner's two-tier lookup checks this path first.

2. **Custom eval dimensions:** Add `project_eval` entries in `factory.md` with
   shell commands that return `{"score": 0.0–1.0}` JSON. These are additive —
   they MUST NOT remove mandatory dimensions.

3. **Contributed workflows:** Add a Python module to
   `factory/workflow/contributed/` with a `meta` dict, a `workflow()` function
   returning a `Workflow`, and an optional `trigger()` function.
   `WorkflowRegistry` auto-discovers these on initialization.

4. **Runner plugins:** Implement the `Runner` protocol in `factory/runners/` and
   register in `factory/runners/__init__.py`. Must provide `metadata()`,
   `build_command()`, `headless()`, and `interactive_run()`.

5. **Language evaluators:** Add new language support via
   `factory/eval/languages/` by implementing the `LanguageEvaluator` interface
   (defined in `factory/eval/languages/base.py`). Register via
   `factory/eval/languages/__init__.py`.

6. **MCP server tools:** `factory/mcp_server.py` exposes factory operations via
   the Model Context Protocol. New tools can be added as handler functions.

7. **Notification adapters:** Implement the `Notifier` protocol
   (`factory/models.py`) with `send_digest()`. Currently implemented:
   `TelegramNotifier` (`factory/notify/telegram.py`).

## Appendix A. Reference Algorithms

### A.1 FEEC Categorization

```
function categorize_hypothesis(text, history):
    lower = lowercase(text)
    if any FIX keyword in lower:
        return FIX
    if any EXPLOIT keyword in lower:
        return EXPLOIT
    if any COMBINE keyword in lower:
        return COMBINE
    return EXPLORE  // catch-all
```

### A.2 Composite Score Computation

```
function compute_composite(hygiene_results, growth_results, project_results,
                           eval_weights, hygiene_overrides, growth_overrides):
    has_project = len(project_results) > 0

    if not has_project:
        hw, gw, pw = 0.50, 0.50, 0.0
    else:
        hw, gw, pw = normalize(eval_weights.hygiene,
                               eval_weights.growth,
                               eval_weights.project)

    hygiene_score = weighted_average(hygiene_results, with_overrides=hygiene_overrides)
    growth_score = weighted_average(growth_results, with_overrides=growth_overrides)
    project_score = weighted_average(project_results) if has_project else 0

    total = hw * hygiene_score + gw * growth_score + pw * project_score
    assert 0.0 <= total <= 1.0

    return CompositeScore(total, all_results, guard_violations, passed)
```

### A.3 Project State Detection

```
function detect_state(project_path):
    if not exists(project_path) or not exists(project_path/.git):
        return NO_REPO

    // MUST check pending review BEFORE full factory
    if exists(.factory/eval_profile.json)
       and eval_profile.human_reviewed == False:
        return EVALS_PENDING_REVIEW

    if exists(.factory/config.json):
        return HAS_FACTORY

    if has_open_plan_issues(project_path):  // only 'plan' label, NOT 'implementation'
        return REPO_INCOMPLETE

    return NO_FACTORY
```

### A.4 Verdict Execution (Gate Node)

```
function execute_gate(gate, context, iteration_counts):
    verdict = evaluate(gate, context)  // agent, fn, or user evaluator

    match verdict:
        case Proceed:
            follow edge with condition=PROCEED
        case Reloop(target, feedback, max_iter):
            key = (gate.id, target)
            iteration_counts[key] += 1
            if iteration_counts[key] > max_iter:
                return Halt("reloop exhaustion: {key}")
            append feedback to target's context
            jump to target node
        case Halt(reason):
            record halt_reason in ExecutionResult
            terminate workflow
```

### A.5 Adversarial Phase Transition

```
function update_adversarial_state(state, active_score, config):
    component = config[state.active_role]

    if active_score >= component.threshold:
        state[state.active_role + "_consecutive_above"] += 1
        state.consecutive_above += 1
    else:
        state[state.active_role + "_consecutive_above"] = 0
        state.consecutive_above = 0

    // Check for phase switch (hysteresis)
    if state.consecutive_above >= config.hysteresis:
        state.active_role = opposite(state.active_role)
        state.consecutive_above = 0

    // Check for convergence (both roles independently)
    if state.generator_consecutive_above >= config.convergence_window
       and state.discriminator_consecutive_above >= config.convergence_window:
        state.converged = True

    persist(state)
```
